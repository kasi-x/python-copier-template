# Translate the docs (Lattice Docs)

This repo's `docs/` tree is translated to Japanese by
[Lattice Docs](https://github.com/politeuma/orimono) (en → ja, more targets
can be added in `lattice.toml`). The translated pages render into
`docs-i18n/ja/` and are committed; the append-only translation records live
under `.lattice/works/`.

## Daily commands

```bash
# after editing English docs — produce + render changed segments
task docs-sync                 # or: lattice docs sync [PATH…] [--lang ja]

# after a human fixed a rendered page in a PR (or locally)
task docs-absorb               # records each change as a `reviewed` segment

# read-only state (per file × language)
lattice docs status            # --json for CI

# build the Japanese site
task docs-ja                   # regenerates zensical.ja.toml, then zensical build -f
```

`task docs-sync` runs the producer (`translategemma:4b` on local Ollama —
set `OLLAMA_HOST` if your Ollama is on another port). CI never calls the
model; the maintainer runs sync locally and commits the results.

## Editing the rendered page is the workflow

If a machine translation is wrong, fix `docs-i18n/ja/<page>` directly and
commit it. The next `task docs-absorb` turns your edit into a human
`reviewed` record with you as the reviewer, so every later regeneration
keeps your fix. Do **not** edit `.lattice/works/` — it is machine-owned
(like a lockfile).

`zensical.ja.toml` is generated by `scripts/gen_zensical_ja.py`; edit
`zensical.toml` and rerun `task docs-ja-config` instead of editing it by
hand.
