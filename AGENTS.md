# Agent Guide for `architekton-py`

This file is for AI coding agents working in this repository. It states how
to run the checks and where edits belong. The human-facing contribution
guide is [CONTRIBUTING.md](CONTRIBUTING.md); this repo is the
copier template itself, so its shape follows the `AGENTS.md` it generates.

## Commands

The `task` runner ([Taskfile.yml](Taskfile.yml)) drives the common commands:

```sh
task fix         # auto-fix formatting and lint
task lint        # ruff format --check + ruff check
task type-check  # basedpyright + pyrefly, vulture, deptry, typos
task hygiene     # merge markers, trailing newlines, YAML, size (CI-mirrored)
task test-fast   # the edit loop: no venv builds, no network (30 s budget)
task check       # lint + type-check + hygiene + test
task regen       # after a questionnaire change: witnesses, batch, tiers, docs
task docs        # build the documentation site
task where -- X  # every file setting X touches
```

Run `task fix` before committing, then the cheapest tier that covers the
change (the blast-radius table in
[CONTRIBUTING.md](CONTRIBUTING.md)): docs-only changes need
`task lint type-check`; template payload (`template/`, `partials/`,
`questions/`) needs `task test-fast` plus `task verify-delta`; a
questionnaire change (`copier.yml`, `questions/*.yml`) needs `task regen`
then `task test-fast`.

## Where to edit

Before editing, run `task where -- <setting>` (or `--json`): it names the
`questions/` file that defines a setting, the derived values it feeds, every
`template/` and `partials/` file that branches on it, and the presets, tests
and docs that name it. Edit those files rather than searching.

- Questionnaire: `questions/NN-<area>.yml`, one file per area; NN is the ask
  order and a question may only read answers from lower numbers.
  `copier.yml` only lists the files and holds template settings.
  Two area files (`03-ros2.yml`, `14-integrations.yml`) are GENERATED from
  `meta/catalog.yml` + `meta/questionnaire/` — edit the meta source
  (areas/ for the area body, fragments/shared/ for reusable questions like
  log_library, `tree.yml` for the variant→area plug table) and run
  `task regen`, never the generated file.
- Presets: `presets/<name>.yml`
- Template tooling (CLI, witnesses, batch runner, docs generator, MCP
- Generated project payload: `template/` (plain names, as in the generated
  project) and the snippets in `partials/`; which files exist for which
  answers is the `.gate` marker beside each path (a sibling `name.gate`, or
  `dir/.gate` for a whole subtree — `questions/99-files.yml` is GENERATED
  from them by `architekton/gen_file_gates.py`, never edit it); the task model is
  `partials/tasks-model.jinja` (dispatcher) + `partials/types/<variant>/`
  `architekton/gen_docs.py --write`; edit their sources, not the output.

## Commits and CI

- Use [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, ...).
- CI runs lint, type-check, the test tiers, the witness render matrix and
  a docs build; keep all of them green.

## Rules for this project

Rules from the [rulebook](https://github.com/politeuma/law-map/tree/main/guidance/sections) that match this project's `.daimonion.yml`
conditions. Follow the lines under each rule; its sources say where the rule comes from, and the
linked rulebook section holds the facts, cases, and prohibited patterns behind it.
Before committing, run `daimonion scan` to match changed lines against these rules. Not legal advice.

### AI and copyright — scraping, training and RAG code must keep the non-enjoyment purpose intact

- Do not bypass robots.txt or other access-refusal measures.
- Do not design RAG that retrieves and re-emits the protected expression itself; extract facts and concepts.
- Do not overfit or fine-tune on a specific body of works in order to imitate it.

Sources: [bunka.go.jp](https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html) · Details: [rulebook `baseline-copyright-ai`](https://github.com/politeuma/law-map/blob/8ba7170987ec356c9183f44e0d0b0eaa94d7c484/guidance/sections/baseline/copyright-ai.md)

### License drift — track each dependency's current license and keep BSL/SSPL out

- Check the current license when adding a dependency and match it against an allowlist.
- Do not let source-available licenses such as BSL/SSPL in without review.
- When a project forks (Terraform to OpenTofu, ...), move to the legitimate successor.

Sources: [hashicorp.com](https://www.hashicorp.com/blog/terraform-is-now-source-available), [opentofu.org](https://opentofu.org/faq/) · Details: [rulebook `baseline-license-drift`](https://github.com/politeuma/law-map/blob/8ba7170987ec356c9183f44e0d0b0eaa94d7c484/guidance/sections/baseline/license-drift.md)

### PKI chain changes — do not hard-code intermediate certificates or issuance chains

- Do not bundle or pin intermediate certificates or issuance chains.
- Verify against the OS/system trust store and keep a way to update it.
- If you pin, pin a set of public keys with a backup key, never a single key.

Sources: [letsencrypt.org](https://letsencrypt.org/certificates/), [letsencrypt.org](https://letsencrypt.org/2023/07/10/cross-sign-expiration), [letsencrypt.org](https://letsencrypt.org/2024/04/12/changes-to-issuance-chains), [community.letsencrypt.org](https://community.letsencrypt.org/t/isrg-root-x2-cross-signed-by-isrg-root-x1/239124), [community.cloudflare.com](https://community.cloudflare.com/t/clarification-about-email-upcoming-lets-encrypt-certificate-chain-change/628713) · Details: [rulebook `baseline-pki-chain`](https://github.com/politeuma/law-map/blob/8ba7170987ec356c9183f44e0d0b0eaa94d7c484/guidance/sections/baseline/pki-chain.md)

### PQC standards — choose ML-KEM/ML-DSA and hybrids for new cryptography

- Use the standard names (ML-KEM, ML-DSA, SLH-DSA), not submission names such as Kyber.
- Key establishment uses ML-KEM; signatures default to ML-DSA with SLH-DSA as the conservative alternative; do not mix the roles.
- Migrate via hybrids (X25519MLKEM768, ...); do not adopt classical algorithms alone in new designs.

Sources: [nist.gov](https://www.nist.gov/news-events/news/2024/08/nist-releases-first-3-finalized-post-quantum-encryption-standards), [csrc.nist.gov](https://csrc.nist.gov/pubs/fips/203/final), [csrc.nist.gov](https://csrc.nist.gov/pubs/fips/204/final), [csrc.nist.gov](https://csrc.nist.gov/pubs/fips/205/final), [csrc.nist.gov](https://csrc.nist.gov/pubs/ir/8547/ipd) · Details: [rulebook `baseline-pqc-fips`](https://github.com/politeuma/law-map/blob/8ba7170987ec356c9183f44e0d0b0eaa94d7c484/guidance/sections/baseline/pqc-fips.md)

### LLM apps / MCP security — least privilege, human approval and output validation by default

- Restrict tool permissions to an allowlist of the minimum CRUD needed.
- Always insert a human approval step before destructive or irreversible operations.
- Validate LLM output structurally before acting on it; never pass it straight to a shell.

Sources: [genai.owasp.org](https://genai.owasp.org/llm-top-10/) · Details: [rulebook `domain-llm-appsec`](https://github.com/politeuma/law-map/blob/8ba7170987ec356c9183f44e0d0b0eaa94d7c484/guidance/sections/domain/llm-appsec.md)
